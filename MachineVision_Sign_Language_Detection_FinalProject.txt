Abstract—This is a report on a Convolutional Neural Network
based system for static sign-language letter detection using the
Sign Language MNIST dataset and live webcam inference.
The system consists of training, evaluation, and a live camera
inference component. The model was trained using PyTorch and
evaluated using a held-out test set. The results include confusion
matrix visualizations and example predictions to qualitatively
analyze per class performance and common confusions. This re-
port documents dataset preparation, model architecture, training
procedure, evaluation, and future enhancements.
Index Terms—Sign Language, Convolutional Neural Network,
PyTorch, Computer Vision, Classification, Confusion Matrix
I. INTRODUCTION
Automatic recognition of sign language is an important
technology for improving accessibility and communication
between hearing-impaired communities and the general public.
This work focuses on static alphabet signs, which are single-
frame images representing letters, using the Sign Language
MNIST dataset and a lightweight CNN model implemented
in PyTorch. The system includes a training pipeline (train.py)
responsible for fitting the model to the dataset, an evaluation
script (test.py) that generates both quantitative metrics and
visual diagnostic outputs, and a live webcam inference script
(camera.py) that performs real-time classification of hand-sign
images captured from a camera stream. This preliminary report
documents the implementation choices, training setup, evalu-
ation procedure, and initial analysis of the model’s behavior,
offering a clear overview of how each component functions
within the complete pipeline.
II. DATASET
The dataset used is the Sign Language MNIST-style CSV
dataset consisting of grayscale 28x28 images stored as flat-
tened rows. Each CSV row contains a class label followed
by 784 pixel intensity values ranging from 0 to 255. Dataset
preprocessing performed in the code involves reading the
CSV file using pandas, reshaping each flattened pixel vector
back into a 28x28 array while casting it to uint8 format, and
applying a sequence of transformations before the data is fed
into the network. These transformations include conversion
to a PIL image, application of optional data augmentations,
conversion to a tensor, and normalization to ensure consistent
scaling across samples.
During training, the code applies several augmentations,
including a random rotation of approximately 10 degrees as
well as normalization of pixel values to have a mean of 0.5and a standard deviation of 0.5. Data loading is implemented
via a PyTorch Dataset class calledSignLanguageMNIST,
combined with a DataLoader that uses a batch size of 64 and
shuffles the data during training to improve generalization by
preventing the model from memorizing sample order.
III. MODELARCHITECTURE
The model is a compact CNN designed for 28x28 grayscale
inputs. Its architecture includes an initial convolutional layer
(Conv2d(1, 32, kernel=3)) followed by a ReLU ac-
tivation function and a max-pooling operation with a 2x2
window. A second convolutional block (Conv2d(32, 64,
kernel=3)) is applied next, again followed by ReLU activa-
tion and a second max-pooling layer. After these convolutional
stages, a dropout layer with probability 0.25 is used to reduce
overfitting by randomly dropping units during training. The
classifier portion consists of a fully connected layer mapping
the flattened feature map (64 *5*5) to 256 units, followed by
another ReLU activation and dropout, and then a final fully
connected layer projecting the 256-dimensional vector to the
number of output classes. The model uses CrossEntropyLoss
as the final loss function.
It is important to note that the final linear layer in the
training code outputs 25 logits. Therefore, users must ensure
that the mapping between class indices and semantic labels (A
to Z with dynamic letters removed) remains consistent across
the dataset, training labels, and the camera-inference script.
The camera script builds a list of alphabet labels from A to
Z but removes the letters J and Z; hence, verifying perfect
alignment between this mapping and the class indices used
during training and evaluation is essential to avoid unnecessary
mismatches.
IV. TRAININGSETUP
Training hyperparameters and settings as implemented in-
clude the use of the Adam optimizer, a learning rate of 0.001,
CrossEntropyLoss as the objective function, a batch size of
64, a total of 10 training epochs, and a dropout rate of 0.25.
The model is trained on a CUDA-capable GPU when one is
available; otherwise, it defaults to the CPU without changing
the logic of the training loop.
The training loop computes the running loss for each epoch
and tracks training accuracy by comparing the number of
correct predictions to the total number of samples in the
training set. Once training concludes, the final model state
dictionary is saved under the filenamesign_model.pt,
making it available for evaluation and real-time inference.
V. EVALUATIONPROCEDURE
Evaluation is implemented intest.py. The evaluation
process begins by loading the saved modelsign_model.pt
and switching it into evaluation mode. Next, the script it-
erates through the test DataLoader using batches of size
64, collecting predictions and corresponding labels across
the entire test set. The script then calculates the over-
all test accuracy and prints it to the console to pro-
vide a simple quantitative metric. Afterward, it computes
and visualizes the confusion matrix using scikit-learn’s
confusion_matrixandConfusionMatrixDisplay,
saving the result tooutputs/confusion_matrix.png.
Finally, a grid of twelve randomly selected test images, along
with their predicted and true labels, is generated and saved as
outputs/sample_predictions.pngto enable qualita-
tive inspection of model behavior.

VIII. LIMITATIONS ANDPOTENTIALIMPROVEMENTS
We recommend several improvements for achieving a more
robust and accurate system. First, label consistency must
be ensured so that the same mapping from class indices
to alphabet letters is used across training, testing, and live
camera inference, particularly because inconsistencies can
lead to misinterpretations. Second, introducing a validation
split enables monitoring of validation accuracy and selectingthe best-performing model checkpoint rather than merely
saving the final epoch. Third, expanding data augmentation
with methods such as translations, brightness and contrast
adjustments, subtle affine transformations, and random erasing
would likely improve robustness against environmental vari-
ability by exposing the model to a broader range of input
conditions. Fourth, the architecture itself could be improved by
adding Batch Normalization, increasing the number of filters
or convolutional layers, or transitioning to modern lightweight
architectures such as MobileNet or EfficientNet-lite to achieve
higher accuracy without sacrificing inference speed. Fifth, en-
hancing the live camera pipeline by incorporating a dedicated
hand detector such as MediaPipe Hands would allow automatic
region-of-interest cropping, improving real-time performance
and reducing background interference. Sixth, applying tempo-
ral smoothing such as majority voting or exponential moving
averages across sequential camera frames would help reduce
classification flicker during live use. Seventh, computing per-
class metrics such as precision, recall, and F1-score using
tools like scikit-learn’sclassification_reportwould
help diagnose specific classes that require additional augmen-
tation or relabeling. Finally, ensuring reproducibility by setting
random seeds for NumPy, PyTorch, and Python’srandom
library, as well as logging hardware, library versions, and other
metadata, would help make experiments more consistent and
easier to replicate.
IX. CONCLUSIONS
This preliminary study demonstrates a working pipeline
for static sign-language alphabet recognition using a compact
PyTorch CNN. The training and testing scripts successfully
produce a saved model and visual evaluation artifacts, such
as the confusion matrix and sampled predictions. The current
model provides a strong starting point, and targeted dataset
improvements, architecture enhancements, and better camera
region-of-interest strategies will further raise performance and
robustness for real-world use.
